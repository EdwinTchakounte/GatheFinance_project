### 3.6 Email

### 3.7 Tests

`pytest` (run complet après corrections) : **744 passés, 0 échec, 0 erreur, 1 skip métier inoffensif**. Total 745 tests collectés.

Le premier run de l'audit affichait 26 fails et 3 erreurs. Les corrections appliquées dans cette session ont tout résolu :

* Bug SQL `FOR UPDATE` sur outer join : ajout de `select_for_update(of=("self",))` dans 4 endroits (`microcampaign_admin.py:413`, `seizure_services.py:293`, `judicial_services.py:144` et `:199`). 19 tests débloqués.
* Test `test_payments_me` : `idempotency_key` attendait un UUID, pas une string. `date_versement` était oublié (NOT NULL). 3 erreurs résolues.
* Test `test_payments_auto_validate` : le fixture créait un Loan sans `loan_request` (OneToOne PROTECT). Ajout du `LoanRequest` préalable. 2 fails résolus.

### 3.8 Bug racine corrigé

Toutes les corrections décrites en §3.7 ont été appliquées et commitées dans cette session. Le runtime est aussi corrigé puisque la saisie d'épargne R1 (Phase C contentieux) et la validation de demande micro-campagne utilisaient le même chemin SQL fautif.

### 3.9 Hook CH-2 (activation membre)

Re-vérifié : il EST implémenté dans `apps_coop/payments/services.py:178` (`_activate_member_if_fees_settled`). Mon premier audit avait raté cette fonction. Le hook bascule automatiquement le Member à ACTIF quand les 3 frais (adhésion + inscription + carnet) sont validés. Idempotent. Émet l'événement `member.activated` une seule fois.

## 5. Portail membre (note 14/20)

11 pages présentes. Refonte 2026 réalisée mais une route index manque.

### 5.1 Conforme 2026

* CH-3 sous-canal placement vs libre (`/epargne/depot`)
* CH-9 sélection `moyen_reception` + note PDF demande crédit
* CH-18 désignation avaliste + consentement Q13
* CH-19 espace prêteur (convention, tranches, funding 24h)
* 3 voies crédit visibles à la soumission (`/credit/demande`)

### 5.2 Dette identifiée

* Route `/[locale]/epargne` index absente. Le portail navigue directement vers `/depot` et `/retrait`. Si un lien externe pointe `/fr/epargne`, le visiteur tombe sur un 404. **Constaté lors de la capture v1**. À créer un index simple (redirect ou page sommaire).
* Pas encore de vue prêteur résumée sur le dashboard principal (le membre doit aller sur `/preteur` pour voir son funding en cours).
* Bouton « Reconduction » présent mais le service backend de reconduction est partiellement implémenté (cf. §6).

### 9.1 4 manques précis à fixer

1. **Hook activation membre (CH-2)** : pas de chaîne automatique `paiement frais complet → Member.statut = ACTIF`. À ajouter un signal post-save sur Payment validé qui vérifie l'agrégat des 3 frais (adhésion + inscription + carnet) puis bascule le statut.
2. **Service de reconduction crédit (Art. 10/11)** : modèle `LoanRenewal` complet mais le service métier qui applique +1 mois, taux 10/15/50, recalcul échéancier sur capital restant dû n'est pas observé. À implémenter dans `loans/services.py`.
3. **Mise en demeure Art. 13 (Phase D)** : champ `mise_en_demeure_count` posé mais pas de cron qui déclenche l'envoi automatique de la lettre type ni l'incrément.
4. **Saisie biens Phase E** : modèle posé, exécution manuelle. À documenter le workflow admin si on n'automatise pas, ou à automatiser le passage en file dédiée.
